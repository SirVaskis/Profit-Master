0.1.3 cooldown and speed investigation:
- Source_ModernAH/Tabs/Auctionator/Mixins/ScanButton.lua selects its controller
  using Config.Options.REPLICATE_SCAN. Source/Config/Main.lua defines that option
  as replicate_scan_3, default false. Profit Master previously forced replicate,
  explaining the mismatch with Auctionator's ability to start a browse scan.
- Source_ModernAH/IncrementalScan/Mixins/Frame.lua: InitiateScan uses the shared
  queued SendBrowseQuery; active flag is doingFullScan (not inProgress). It gathers
  BrowseResultInfo in rawScan, then emits IncrementalScan.Events.ScanComplete with
  that array after processing. Events.lua also defines start/progress/failure.
- AddPrices stores resultInfo.minPrice as the database price with totalQuantity
  as availability; this is an item-price summary, not a single stack buyout.
- Matching Blizzard AuctionHouseDocumentation.lua documents BrowseResultInfo,
  itemKey fields and SendSearchQuery. Matching Blizzard_AuctionHouseBrowseResultsFrame
  passes browseResult to SelectBrowseResult and uses appearanceLink with a cached
  C_Item.GetItemInfo(itemID) link fallback for display. Profit Master uses the same
  fallback only for estimates; live buys still use each result's exact itemLink.
https://github.com/Gethe/wow-ui-source/blob/4cd0ab752a77164f654ccbca9d0c1fe8dafceebe/Interface/AddOns/Blizzard_AuctionHouseUI/Shared/Blizzard_AuctionHouseBrowseResultsFrame.lua
- Source-local inefficiencies: duplicate exact-link vendor lookups, a second lookup
  for every skipped listing, 250-entry batches with a 0.01s requested delay, and
  fresh vendor calculations for every preceding row while locating a Buy auction.
- New processing reuses per-pass exact-link values, removes that second lookup,
  caps batches at 1000 with a zero-delay yield, and values only the selected auction
  during Buy revalidation. A browse candidate searches its exact key via
  SendSearchQuery instead of a broad SendSellSearchQuery over all variants.
- Offline comparison: tools/Benchmark-ProfitMaster.lua, saved 0.1.2 Deals.lua in
  scratch/profit-master-0.1.2. For 200000 listings over 100 exact links, vendor-info
  calls fell from 200000 to 100, with identical 100000 deals / 100000 copper profit.
  Trivial mocked calls took 0.002s baseline versus 0.004s cached: this does NOT
  demonstrate lower wall-clock latency or a game-speed multiplier. The confirmed
  benefit is fewer engine API lookups and scheduled batches. Network, real engine
  lookup cost, UI responsiveness and end-to-end latency require the user's test.
